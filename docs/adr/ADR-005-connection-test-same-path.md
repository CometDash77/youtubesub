# ADR-005: 测试连接与生产同一条路径

状态: 已接受 (2026-09-21).

背景: "测试连接"要回答的是"这份配置到底能不能翻译". 备选做法有二: 只探端点(GET /models 或空跑一次请求), 或者单独写一条轻量探测路径. 前者会把"能连上但翻不了"报成通过(模型名写错也能绿灯), 后者测的不是用户真正会跑的那条路, 绿灯没有可迁移的证据.

决定: 测试与生产走**同一条调用路径与同一套参数** —— 同一个 cfg, 同一个 translate_group(含它的重试与退避), 唯一差异是**不读也不写 TranslationCache**; 通过门槛在"真发一句最小翻译、拿到结构合法的非空译文", 端点探测(GET /models, 三态)只用于失败定位、不作门槛; Mock 模式是第三种结论(mock), 完全不发网络请求. 由此得到不变式: **红灯 = 生产也会红**.

后果: 一次点击真实消耗最小请求额度(重试下最坏 4 次尝试), 因此绝不自动触发、结果里带 attempts 字段; 最坏墙钟约 87s, 因此必须工作线程 + 进度 + 取消; 测试绕开队列与缓存, 因此与 max_concurrent 无关. 端点探测的三态判定也是这条不变式的产物: /models 不是 OpenAI-compatible 的必备端点, 拿它当门槛就会造出假红灯.
