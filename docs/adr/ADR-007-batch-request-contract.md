# ADR-007: 窗口预取改按时间量纲, 并引入"填充即分块"的批请求

状态: 已接受 (2026-09-21).

背景: 预取原来按**句数** (PREFETCH_GROUPS = 4: 当前组提紧急优先级, 其后 4 组提普通优先级), 提前量随字幕疏密漂移; 且预取被"上下文开关"顺带控制 (关掉上下文连预取一起关掉, 是耦合缺陷而非设计); 窗口一旦放大又没有任何爆量闸. 用户指定 kiss-translator 为参照实现并已取证 (#3): 它的"提前批翻译"是**播放时间窗口** (preTrans 默认 90 秒) + **30 秒扫描节流** + **逐 cue 提交**, "批"来自一个与 DOM 段落翻译共用的**通用异步 BatchQueue** (batchSize=20 / batchLength=10000 字符 / batchInterval=400ms), 字幕路径本身没有批大小参数; 它 seek 时只取消节流定时器、不处理在途请求 (作者自认缺陷). 与之相比本项目**一组一请求**, 同窗口下请求数高一个量级 (估算 5–10 倍). 决策票 #9 就目标 / 量纲 / 触发 / 批契约 / 降级 / 并发 / 取消逐条裁定, 结论固化在规格 #24.

决定: **提前量改用时间量纲, 并新增批请求;** 但两处都不照搬参照实现的形态.

- 预取窗口 = **当前播放点之后 90 秒**, 另设**组数硬上限** (默认 20), 两者取先到者. 提前量以**秒**对外表达. **不做**按播放速率缩放窗口 (墙钟口径在 2 倍速下会覆盖双倍视频内容, 比参照实现更差).
- 触发保持**事件原生增量** (播放进度跨组即重算窗口). **不引入**参照实现的 30 秒扫描节流 —— 那是对它"定时扫描"结构的补偿, 本项目的事件触发在稳态下每次只新增一组, 天然更平滑. seek 之后加一段**去抖** (默认 400 毫秒, 本项目自定值, 非照搬) 再重填, 避免拖拽进度条反复整窗重发. 屏幕上正在显示那句 (紧急优先级) 永不节流、永不去抖.
- **在途请求一律不中断.** 理由是缓存 identity 与播放位置无关, 在途结果仍有缓存价值, 回到该位置会命中 —— 这与参照实现"seek 时在途请求是白费"的结论**不同**, 不得照抄它"只取消定时器就算处理完".
- **批只在窗口填充的爆发点产生** (首次播放 / seek 去抖后重填 / 限流退避后补课): 把待提交的组按 **≤8 组、≤8000 字符同步切块**后成批发出; **稳态仍是"一组一请求"**, 播到哪翻到哪的行为不变. **不引入**定时器或异步收集器.
- 批的输出契约 = **全局连续编号** `1|译文 … T|译文` (T = 批内各组字幕行数之和), 沿用既有"**精确全覆盖**"校验. **不可放宽**: 模型丢行后常重新连续编号, 缺失行之后整体错位且无法从文本检出, 所以"缺哪补哪"被禁止.
- 批失败 = **整批作废**: 不重发、不拆分、不重试, 该批各组不写缓存、不留占位符, 播放点到达时走现成的**逐组紧急补翻**. 批不落盘、无残留状态.
- 缓存写入粒度仍是**组**, 批没有自己的 identity; 批成功时按各已知组行数确定性切片、逐组写回提交前算好的 identity. 批内**每组仍带自己的上下文**, 以维持不变式: **同一个组无论走批还是单发, cache identity 必须逐字节相同**.

后果:

- **批量只在爆发点生效, 稳态成本不降**; 与参照实现的请求数量级差不会因此消失. 这一点容易被误读成"整体更快更省", 规格里已写死.
- 批的失败粒度是**整批**: 一窗预取可能整体落空, 最坏等于改造前的行为 (不会更差).
- 批内每组保留上下文使输入膨胀约 3 倍, 同一字符上限下可装的组数降到约三分之一, 批容量因此比参照实现的通用批参数更保守.
- 高倍速下同样时长的墙钟预算减半、吞吐需求翻倍; 组数上限不解决这一项, 由"深退避期间削减普通优先级"承接.
- **考虑过并否决**: 分组块标记输出 (失败可定位到具体组, 但要新增一套解析器与新契约; 定位能力可用后续"批失败后二分递归"补, 已留钩子); 二分递归降级 (复杂度换边际收益, 不进第一版); 批内去掉上下文 (破坏 identity 不变式, 导致同一组被重复付费); 稳态收集窗 (降请求数要牺牲事件触发的粒度); 整片预批 (参照实现没有该能力).
- **参数无实测依据**: 组数硬上限 / 批组数上限 / 批字符上限三个默认值待真实 Key 到位后用"译文就绪率"校准; 若实测模型对编号契约的遵循度差, 先缩小批组数上限, 再考虑改用分组标记.
- 实现拆分与验收用例见规格 issue「提前批翻译：预取窗口与批请求契约（规格）」#24.
