# ADR-007: 离散时间段预取与整段批请求

状态: 已接受（2026-09-24 修订；取代下方所列旧契约）

## 背景

初版把预取窗口填充时的请求按最多 8 组 / 8000 字符切块，并以全局连续编号的竖线行协议返回。智能上下文改造需要将窗口定义成可重复认领的离散时间段，并让每段字幕一次性翻译；切片和编号行协议因此不再适用。预取描述何时提交前方字幕，批量描述一次请求包含多少字幕，两者仍是正交维度。

## 决定

- 段边界按全视频绝对时间网格 `[0,90)、[90,180)…` 秒计算；段号是时间戳的纯函数。seek 到某时刻认领包含该时刻的段，使用既有 400ms debounce；重复 seek 对同段幂等。
- 预取提前量默认 90 秒，允许值域 30–120 秒；它独立于固定的 90 秒批段网格。提前量按视频时间计量，不按播放速率缩放。
- 每批包含被触发时间段内的全部字幕组，一次性送出，不设 8 组或 8000 字符切片上限。user 消息中的字幕批不得截断。
- 播放进入当前段 60 秒后（距段末 30 秒）触发下一段翻译；阈值是只读配置。稳态只提交新段增量。同一时刻至多一个普通批次在途；紧急单组请求可插队。
- 首次播放、seek 去抖重填和退避补课沿用预取调度；不以智能上下文开关控制预取。
- provider 响应改为按批内索引键映射的 JSON。解析器可剥离三反引号 `json` 围栏；必须覆盖索引 `1..N` 且每项非空，允许乱序并忽略多余键。格式错误、缺键或空值使整批作废，不部分写缓存，交现有紧急单组路径补翻；记录可观察的错误类别。
- 保留请求未完成时不取消的原则。成功批次按已知组边界拆回逐组缓存；批次本身没有独立缓存身份。批失败不引入新的重试协议。
- 已知残余风险：模型可能丢键或改变长文本转义；严格整批校验将此类响应作废，随后由紧急路径补翻。该取舍已确认接受。

## 后果与范围

预取和批量可以独立开关或调整；本 ADR 定义的段批只改变请求形态，不把预取提前量重新定义为批大小。整段一次性发送会让极长区段请求变大，轨道上下文另由 [ADR-009](ADR-009-context-window-and-cache-identity.md) 的只读双锚上限约束，批字幕本身仍完整。

## 修订历史

2026-09-24 修订取代 2026-09-21 原决定中的：每批最多 8 组 / 8000 字符、稳态单组发送作为硬契约、全局连续编号竖线行响应格式。其余与本修订不冲突的预取原则继续有效。决议来源：智能上下文 map 的批定义、接力、JSON 协议、绝对网格与测试决议（Notes #4、#6、#8、#17、#18）。
