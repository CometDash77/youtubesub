# ADR-011: API Key 明文存盘并明示

状态: 已接受 (2026-09-22).

背景: `api_key` 以明文存于 `%APPDATA%\SubOverlay\setting.json` (原子写 + 损坏留 `.bak`), 而 #4 决策把「打开配置目录」摆到了用户眼前 —— 盘上到底怎么存, 从未对用户说过。本 map 已锁定的相邻事实: key 永不出现在日志、`/status` 端点与诊断报告 (#4 / #5 / ADR-005), 面板回显「已保存 N 字符 · 留空 = 不改动」且**回显永不明文** (#4), 缓存 identity 故意排除 api_key (queue_cache)。未定的是**存盘形态**三选一: ① DPAPI 加密; ② 不存 (每次重输); ③ 保留明文 + 明示。

决定:
- **保留明文 JSON, 不引入 DPAPI, 不做「不存」**。
- **DPAPI 的收益-代价账**: 收益 = 防「配置文件被拷到另一台机器后离线明文可读」; 局限 = 密钥绑定 Windows 用户账户, **同账户下任何进程都能解密**, 防不住本机的真正威胁面; 代价 = 跨机迁移配置静默失效、原子写/.bak 损坏恢复语义复杂化、测试面扩大、「打开配置目录可读」的透明性受损、非 Windows 平台分叉。单机桌面浮窗场景下代价 > 收益。
- **「不存」直接否决**: 与 #4 的「已保存 N 字符」证据链矛盾 (没存就无从回显), 每次启动重输是配置可信的倒退。
- **明示三处, 把「明文」本身告知用户**: ① 面板 API Key 行说明 (tooltip 或行内注释: 明文保存于本机配置文件, 不上传、不进日志/诊断); ② README / docs/MANUAL-ACCEPTANCE.md 一句话; ③ SPEC 第一部「配置可信」实现清单登记。
- **既有不变式全部不变**: key 永不进日志 / 端点 / 报告 / 缓存 identity; 面板回显永不明文; 不进任何 issue 正文与评论。
- **翻盘点 (重新开此决定的唯一触发)**: 出现配置**导出 / 分享 / 云同步**能力 (当前均为 map 的 Out of scope) —— 届时**导出格式必须加密** (DPAPI 或口令派生), 单机原盘存储在此之前不重开。

后果:
- 明文可被同账户任意进程读取、`setting.json` 随拷贝外带 —— 明示即知情同意; 本机文件权限依托 `%APPDATA%` 用户目录的默认 ACL, 不另做 chmod。
- 面板、文档、SPEC 三处明示由规格实现承接 (单点小决议, 按 #20 决议进 SPEC 第一部, 不另开规格单)。
- 与 #4 的「回显永不明文」合起来构成完整口径: **屏上不显明文, 盘上明文但挑明**。
