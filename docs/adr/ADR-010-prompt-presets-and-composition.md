# ADR-010: 提示词预设与智能上下文组装

状态: 已接受（2026-09-24 修订；组装契约取代原邻组与编号行协议）

## 背景

原 ADR-010 定义预设正文、邻组标签行和 `N|line` 对齐指令的组装次序。智能上下文改造要求将全轨和视频元数据作为稳定结构化上下文注入 system，同时让 user 消息只承载本次待译批次，并采用机器可解析的 JSON 批响应。

## 决定

- 保留 `build_instructions` 为唯一 system prompt 组装函数。system 由可编辑预设段与程序生成的固定协议段组成；协议段按固定顺序包含 `[VIDEO TITLE]`、`[VIDEO DESCRIPTION]`、`[FULL TRANSCRIPT]`（带时间戳），以及要求翻译 user 消息中批次的固定指令。标题或简介缺失时省略对应节。预设段只定义翻译风格、目标语言和术语，不重复协议段职责。
- user 消息为纯待翻译字幕批，不添加邻组标签、编号行协议或其他上下文。模型批响应使用 [ADR-007](ADR-007-batch-request-contract.md) 定义的索引 JSON。
- 同一视频、相同字段、播放点和配置下，system prompt 字节稳定；节标题与协议文本固定，不提供用户配置项。播放点变化可能按 ADR-009 改变双锚截断后的轨道文本。预设升级只影响默认预设，不改写用户自定义预设。
- 预览、测试连接与生产翻译共用同一组装函数。紧急单组请求也使用相同的全轨 system prompt，保持每轨一个 system prompt。
- 保留既有内置与自定义预设管理、配置迁移和缓存身份规则中与新协议不冲突的决定。GPL-3.0 参照项目只用于 clean-room 结构研究，不复用代码或原文；新默认预设措辞以独立 research 票提案为输入。

## 后果与范围

协议段内容或顺序的变化属于契约变化，须同步更新快照/契约测试。新增视频字段由 register 帧提供；旧端缺字段仍须可用并省略相应节。完整测试契约见智能上下文 map 的测试票。

## 修订历史

2026-09-24 修订取代 2026-09-22 原决定中的邻组上下文标签行与 `N|line` 对齐协议；预设管理、单一组装函数与缓存身份分叉等未冲突决定继续有效。决议来源：智能上下文 map 的分节布局、JSON 协议、预设边界、稳定性、缺省行为与紧急路径决议（Notes #5、#7–#8、#11、#14、#18）。
