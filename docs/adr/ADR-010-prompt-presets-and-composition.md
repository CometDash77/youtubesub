# ADR-010: 提示词预设、组装次序与生效预览

状态: 已接受 (2026-09-22).

背景: 提示词现状是 settings `prompt.system` 单个自由字符串 + 面板一个多行文本框 (settings.py / app.py SettingsDialog), 没有预设、没有 `prompt.context_groups` 的任何 UI 入口 (键只存在于 setting.json), 也没有"最终发出去是什么"的预览。组装次序在 provider.py `translate_group` 里已写死 (预设正文 → 上下文标签行 → N|line 对齐指令), 但没有任何测试钉住这个形状; 缓存侧 identity 含 `instructions`、翻译命名空间含系统提示词 (ADR-008), 所以换提示词天然分叉缓存 —— 这条性质目前只是实现事实, 没有被登记为契约。参照实现 kiss-translator 的提示词管理是: 10 条内置预设写死源码、4 个分类, 预设不可编辑不可删除、只能"复制成自定义", 自定义存全局 setting 的 `prompts` 数组, 13 个占位符 + 三级解析; 其字幕预设正文是 boundary-v3 **断句**协议 (本项目只翻不切, 无对应物), 另有视频级摘要经 `{{summary}}` 注入系统提示词。kiss 是 GPL-3.0: 只允许行为与存储结构对齐, clean-room 重写、不抄文本。

决定:
- **预设结构对齐、文本自拟**: 内置预设 **3 条、单分类「字幕翻译」** (`default` = 现行默认文本逐字保留, `literal` 术语直译, `natural` 口语自然), 锁在代码里 —— 不可编辑、不可删除、不落盘 (对齐 kiss"预设永远从代码取"的语义); 不照搬它的 10 条 4 分类 (那服务网页翻译 / 批量 / AI 词典多用途, 本项目只有字幕翻译一个用途) 与 13 个占位符体系。
- **自定义存主配置文件**: `settings.json` 的 `prompt.presets` 数组 (`{id, name, text}`, `id = prompt_<uuid8>`), **不设独立文件** —— 配置可信的证据链是"单文件、单路径、页脚常驻、上次保存" (#4), 第二个文件会撕开这条链; 预设体量小, JSON 装得下。
- **schema 迁移单向一次**: `prompt.active` (预设 id) + `prompt.presets` (自定义数组) 取代 `prompt.system`; 旧 `prompt.system` 内容非空且不等于内置默认 → 导入为名为「旧版自定义」的自定义预设并设为 active; 等于默认或为空 → 直接丢弃。不保留双源。
- **UI 形态**: 预设下拉 (内置 ∕ 我的预设两组) + 「复制为自定义」+ 重命名 / 删除 (仅自定义可用, 内置上为 no-op —— 对齐 kiss 的 preset-slug no-op 语义) + 编辑框 (选中内置时只读) + **只读「生效提示词预览」**; 删除当前 active 的自定义 → 回退内置 `default` (对齐它的 removePromptReferences 回退语义); 顺带兑现 ADR-009 的移交, 暴露 `prompt.context_groups` 复选框「携带上下文 (前后各 1 组)」; 全部沿用 #4 的 OK/Cancel 写盘语义。
- **组装次序写死, 无覆盖关系**: 最终 system = **预设正文 + 上下文标签行 (开关开且有邻组时) + N|line 对齐指令 (expected_lines > 1 时)**, user 消息 = 纯当前句。三段职责: 预设是**任务定义段** (用户唯一可编辑的段); 上下文与 N|line 是**协议段** —— 程序生成、永不出现在编辑框、不可被预设覆盖或删除。不引入占位符系统: 预设正文是纯文本, 没有会被替换的洞。此即现状 provider.py 行为的契约化, 不改字节。
- **缓存零失效逻辑, 换预设即分叉**: 切换或删除预设 → `instructions` 变 → identity 与翻译命名空间变 (ADR-008) → 旧译文不可达、内存译文作废、当前句重调度。**固化为契约: 切换预设必须改变 identity**, 加回归测试钉住 (登记防删, 与 ADR-009"identity 含上下文"同一防线)。
- **预览与测试连接共用同一组装函数, 不建第二套**: 测试连接 (#23 / ADR-005) 与生产走同一条 `translate_group`, 因此自动使用同一组装结果 —— 同路径不变式覆盖提示词; 面板预览直接调用该组装函数显示结果 (同一函数产出, 非复制文本), 测试连接不新增预览端点、不单独挑选提示词。
- **视频级摘要与占位符系统不引入**: 需要额外网络请求与失败面、摘要进 identity 是又一次身份方案变更 (kiss 自己按 {apiSlug, videoId} 缓存摘要、换提示词不重算, 属补丁态), 收益 (长视频术语一致性) 已被 ±1 组上下文 + 预设中的术语指令部分覆盖。登记出 map 的 Not yet specified; 翻盘点 = 真实 Key 实测发现长视频一致性不足时, 重新画范围另票。

后果:
- 与 kiss 的登记差异: 预设文本自拟 (GPL-3.0 红线)、单分类、无占位符、自定义存主配置而非独立 storage key、不提供 user 模板编辑 (user 消息永远是纯当前句)。
- 换预设 = 全量缓存分叉 —— 与 ADR-009 相同的"正确性优先于命中率"兑换, 不回退。
- 旧 `prompt.system` 的迁移是一次性、单向的; 迁移后该字段不再是双源。
- 删除 active 自定义回退默认, 用户不会陷入"没有提示词"的空态。
- 摘要不引入是范围决策而非永久否决: 真实 Key 实测翻盘时另票重开。
- 实现拆分与验收用例见规格 issue (「提示词管理: 预设、组合与生效预览 (规格)」)。
