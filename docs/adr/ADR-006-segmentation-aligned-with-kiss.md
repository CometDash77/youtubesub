# ADR-006: 断句判据对齐 kiss-translator 的规则分支

状态: 已接受 (2026-09-21). 取代 ADR-004 的**断句判据**部分; ADR-004 的**翻译单位 = 句子组**部分继续有效.

背景: 现有判据继承自 yt-dual-subs 的私有启发式 (lastOff 词级停顿 600ms / 32 词 / 280 字符 / 超限回切到组内最大停顿点), 只能靠观感判断好坏. 用户指定 kiss-translator 为参照实现, 并排定优先级 —— **行为对齐 ≻ 译文质量 ≻ 修具体缺陷**, 冲突时以与参照实现一致为准; 于是"要不要照搬"不再是问题, 问题只剩"照搬到哪一层、怎么落". 事实基线 (参照实现 dev @ 0e6e6a79): 它的规则断句**没有规则表文件**, 判据与 46 词英语连词表硬编码在函数体内; 它的输入在自动字幕轨上是段(词)级单位, 且粗粒度时按字长比例**伪造**词级时间戳; 本项目的 Cue **同时是显示单位与对齐单位** (模型返回行数必须等于组内 cue 数, 译文逐 cue 回填). 参照实现是 **GPL-3.0**.

决定: 判据整体替换为参照实现「规则断句」分支的**行为等价实现**, clean-room 重写 (GPL 约束下不得复制其代码):
- 按**语言**分岔. 空格语系走六条判据: 真实静音基准 (下一段起点减上一段终点) + 1000ms 阈值; 15 词上限只在"缓冲末行以逗号结尾"时触发; 缓冲跨度达 10000ms 即断; 溢出**无回退** (哪条触发就在哪切); 命中"非语音段"的段直接剔除、不翻译并强制在其前断句; 以方括号、圆括号或音符记号开头的行前强制断句. 中文与日韩等无空格语系走另一支: **质量闸门优先** (超过 5 个字符的行占比大于 50% 即原样返回、完全不断句), 未触发时按 30 字符上限 + 1000ms 静音落句, 落句判据允许尾随的右引号与右括号.
- 长句二次切分照搬 (超阈值的长句取其覆盖段以启用弱暂停的方式重跑, 连词表随之生效), 阈值**写死**为参照实现的配置默认值 100.
- 按**轨道类型**决定是否承诺一致: 手动轨承诺断点一致; 自动字幕轨共用同一套判据但**不承诺一致** (参照实现在该轨是词级/伪造词级单位, 要对齐只能重开翻译单位).
- 旧启发式**整块删除、不并存**; 判据**不可配置**, 不新增任何设置键、不提供编辑入口.
- 输入粒度不变 (一条 cue = 一个 json3 event 内全部 segment 的拼接), 仅段间拼接改为参照实现的空格分隔; 线上协议里的词级偏移字段**保留但不再参与分句**.

后果:
- **已知且接受的行为变化**: 中文手动轨在闸门触发时等于"一行一组" (合并行为归零); 非语音行不再出现译文; 组整体变长 (10 秒时长 + 逗号门 + 无回退) 导致单请求行数变多, "行数失配即整组降级为单行"的降级路径会被更频繁触发 —— 这是"行为对齐优先于译文质量"这笔兑换率的账单.
- **继承参照实现的缺陷**: 语言前缀二分对中英混排误伤 (英文单词被当作连续字符流、30 字符即断); 二次切分用的连词表只有英文.
- **残留差异**: cue 仍是 event 级, 一个 event 内含多段时与参照实现的段级单位不等价 (有意接受, 改它等于半步走回"重开翻译单位").
- **未决 (另票)**: 自动字幕轨的断点一致性、词级偏移字段的正式废弃说明、解析改为按段展开的时机、AI 与统计断句的归属.
- 判据表驱动的验收用例与实现拆分见规格 issue (「字幕断句判据对齐 kiss-translator（规格）」).
