# ADR-009: 邻组上下文的窗口、拼接与缓存身份

状态: 已接受 (2026-09-22).

背景: 本项目的"智能上下文"现状是以句子组为单位的**邻组窗口**: 提交一组翻译时取轨道组数组中前一组与后一组的**原文** (engine.py `_submit_group`), 受 settings `prompt.context_groups` (默认开) 控制. 上下文在**身份层**以 " || " 拼进 prompt 参与 `cache_identity` (engine.py `_identity`), 在**线上报文**里以标签行追加进系统提示词、用户消息保持纯当前句 (provider.py `translate_group`). 参照实现 kiss-translator 的"智能上下文"实为两个独立功能: ① 对话历史 (useContext / contextSize=3, 按 apiSlug 内存单例, **不进缓存键**, 启用时批次并发强制 1, 其字幕路径实际不传历史); ② 视频级摘要 (占位符注入系统提示词, 摘要前 50 字符进缓存键). 取证已判定"上下文不进缓存键"为本项目**明确不照搬**项 (kiss 是 GPL-3.0, 只做行为对齐、clean-room 重写).

决定:
- **窗口固定前后各 1 个句子组**, 不引入数值配置、不做 token 计量; 不照搬 contextSize=3 (那是 chat 轮次机制, 对其字幕路径无对应物), 不引入对话历史机制 (它要求批次并发降为 1, 与本项目并行队列冲突, 且参照实现的字幕路径自己也不使用).
- **拼接分两层且都写死**: 线上报文 = 上下文以 `Previous/Next line (context only, do not translate): ` 标签行进系统提示词, 用户消息保持纯当前句 —— 与参照实现"上下文全在 system、user 消息纯净"的原则等价; 身份层 = " || " 拼接仅是 `cache_identity` 的规范化编码, 永不上线. 分隔符与措辞不可配置: 改动它们 = 身份方案变更 = 全量缓存失效, 零用户收益.
- **缓存身份继续包含上下文** (现状保留): 上下文的任何变化 (开关翻转、邻组原文变化) 必须改变 identity. 这是与参照实现的**刻意差异** —— 照搬"上下文不进缓存键"会复活"开关上下文命中同一缓存"的缺陷 (与 issue #31 的 Mock 污染同型).
- **窗口是位置确定性的**: 邻组取自轨道组数组的 ±1 索引、取的是**原文**, 与翻译完成顺序、播放历史无关 —— 视频首尾自然缺省 (空串则该标签行不出现), seek 之后、批与单发、任何到达路径下同一组的 identity 逐字节相同. 不做去重 (无累积状态、无重复风险), 不做字符截断 (组长度归断句规则管, 见 ADR-006).
- **可配置面 = 唯一布尔开关 `prompt.context_groups`** (默认开): 只能整体携带或不携带上下文, 不提供窗口大小与策略选择, settings schema 与真值语义不变. 该开关只语义化提示词; 现状 engine.py 同时把它当作预取门控 (`PREFETCH_GROUPS = 4` 的前瞻提交) 属**语义串扰** —— 预取是调度行为、归提前批翻译 (#9 / #24) 的域, 应解耦为无条件; 实现归规格 issue.
- **范围边界**: 参照实现的视频级摘要 (②) 不在本决策内 —— 它牵动系统提示词占位符与提示词形态, 归"提示词管理"票 (#8) 决定; 开关的面板暴露 (setting.json 有键、UI 无入口) 同样归 #8 的提示词 UI 一并定. 本票只登记移交, 不实现.

后果:
- 上下文开关、邻组文本、编码任一变化都会分叉缓存 —— 这是"正确性优先于命中率"的既有兑换, 不回退.
- 不截断意味着 ADR-006 的断句规格落地前, 旧启发式产生的长组会撑大上下文 —— 残余风险, 由规格 #22 落地收敛.
- 预取解耦是行为变化: `context_groups=0` 时预取照常发生 (请求时机提前、总量不变); 依赖旧耦合的测试 (test_engine.py 的 Mock 缓存计数用例以 `context_groups=0` 换取精确调用计数) 需同步改写, 其验收意图不变.
- 视频摘要与开关的 UI 暴露移交 #8; 若 #8 不接, 由 map 登记为后续票.
- 验收用例与实现拆分见规格 issue (「智能上下文：窗口与拼接契约（规格）」).
