# ADR-009: 智能上下文与缓存身份

状态: 已接受（2026-09-24 修订；取代原邻组上下文契约）

## 背景

原 ADR-009 把“智能上下文”定义为当前字幕组前后各一组原文。全轨翻译需要让每个批次和紧急单组请求都共享同视频级信息，使术语与指代在不同时间段保持一致；原 ±1 邻组采样和对应提示词标签不再满足目标。

## 决定

- 复用设置键 `prompt.context_groups`，默认开启。语义扩为携带结构化智能上下文；仅更新复选框文案为「携带智能上下文（全轨+标题+简介）」，不新增设置、不迁移数据。
- 上下文由视频标题、视频简介、带时间戳的全轨字幕构成，放在 system prompt 的固定分节块中。用户脚本从 `meta[name=description]` 读取简介，并清理标题末尾 ` - YouTube`；register 帧增加可选字段，桌面端向后兼容。缺失字段的节省略。全轨超过只读 `max_context_chars`（默认 20000 字符）时按播放点双锚截断，每次请求按当前播放点重新计算：优先保留已播段起点至播放点，以及播放点至片尾的待播段；待播段装不下时先截其远端尾部，待播段可完整保留时再截已播远端老头部。批次字幕在 user 消息中永不截断。
- 紧急单组翻译同样携带全轨上下文。每条字幕轨只构造一个 system prompt，不另建命名空间。
- 缓存身份方案保持现行 v2：不升级版本、不清缓存、不增加哈希或版本串。上下文通过既有 prompt 参与身份的路径生效。
- 接受残余风险：字幕刷新或换轨后，已经翻译并命中旧缓存的组可能保留基于旧上下文的译文；本次不新增失效机制。
- 删除 `_context_texts` 的 ±1 邻组采样及 Previous/Next line 提示词标签。智能上下文只影响提示内容，不控制预取；预取行为归 [ADR-007](ADR-007-batch-request-contract.md)。

## 后果与范围

全轨上下文可能很长，因此必须执行双锚截断；该上限只约束 system 中的轨道上下文，不裁剪待翻译批次。身份版本保持 v2 意味着同一身份方案内的字幕刷新风险已明确接受。标题、简介的来源与 register 帧兼容性见该改造的用户脚本协议票。

## 修订历史

2026-09-24 修订取代 2026-09-22 原决定中的前后各一组窗口、邻组文本参与身份、邻组标签行和无上下文长度上限等条款。原“上下文不应控制预取”的正交性结论继续有效。决议来源：智能上下文 map 的范围、开关、缓存、字段、紧急路径、截断、旧机件清理决议（Notes #3、#9–#10、#12–#16）。
