## 图怎么来的（可复现）

两块都不是「照着画一遍」，而是直接跑现码：

1. **浮窗孅图 = 真绘制路径**。每张浮窗都是 `desktop/suboverlay/overlay.py` 的 `OverlayWindow`

   再原样贴在棋盘格 / 示例画面上。字号、行距、折行、描边宽度、圆角、分隔线全部由
   `paintEvent` 生成，不是手画。
2. **调参页窗体 = 真 `TuningPage`**。仅两处按 #174/#177 的**拟议**形态加料：
   `_group_card("display")` 被包了一层，往「显示」组顶部插一行预览画布 + 6 行新键；
   6 行新键的控件用同一个库（`ComboBox` / `PushButton`）造，形态是假的、皮肤是真的。
   既有 8 键与另外两组一格未动。

参数：浮窗尺寸取**本机真实运行值 295×171**；正文/译文文案为示例；描边 1.5；字号 8。
棋盘格边长 12px（可调，仅作观感参考）。

## 01-concept.png — 四色键能改什么

| 行 | 展示的待裁项 |
| --- | --- |
| A | 四色键**缺失**时的回退：原文白字黑边 / 译文 `#FFE082` —— 即今天的硬编码值 |
| B | 四色键改成自定义：原文青字黑边 / 译文白字深蓝边 |

每行左半 = 透明棋盘格预览底（即 #176 定的浮窗预览观感），右半 = 垫一张示例画面。

## 02-opacity-matrix.png — 不透明度是否可读

四档 `bg_opacity`（255 / 180 / 90 / 40），每档两列（左：棋盘格预览底；右：示例画面底）。

- **255 与 180**：两行都清楚，棋盘格与画面都不透。
- **90**：译文行开始失去对比（棋盘格从字里透出来），原文行仍可读。
- **40**：底板基本消失，~`#FFE082` 的译文行最糊；此时**黑描边是唯一撑住可读性的东西**（`stroke=1.5`）。

## 03-tuning-display-group.png — 6 行新键排下来拥不拥挤

真调参页截图（`TuningPage` + 「显示」组顶部插入的预览画布与 6 行）。读图要点：

- 预览画布取真浮窗逻辑尺寸 **295×143**（= 171 − 底部 24px 状态行带，口径同
  `desktop/tests/test_overlay_labels.py:217`），1:1 贴进 `130px` 标签列 + 控件列 + 提示列的网格。
- 6 行新键把「显示」组从 8 行拉到 14 行 + 1 张画布；卡片本身仍在一屏内（整页 4 张卡）。
- 色块 = 库的 `PushButton`，文字是 `#RRGGBB`（沿用 `TuningPage._color_text` 口径），
  右边跟一个「改回默认」小按钮（#177 待裁项 2 的一个候选形态）。
- 字体下拉是库的 `ComboBox`，默认项 `Microsoft YaHei UI`。

## 需要维护者拍板/留意的三点

1. **棋盘格够不够像 PS**：格边长 12px、`#FFFFFF`/`#CCCCCC`。嫌细/嫌粗改一个数即可。
2. **低不透明度下译文色的可读性**：`bg_opacity ≤ 90` 时 `#FFE082` 在亮底上发糊，
   黑描边是主要依靠。#177 若裁「描边色可调」，这条就是用户能自己踩到的坑。
3. **拥挤度**：四色键各带一个「改回默认」按钮时，控件列被切成两段；若不想要这个按钮，
   四行会明显更松。这是 #177 待裁项 2 的取舍依据。

## 诚实边界

- 本机 offscreen 平台的字体库只认出 57 个字族，**不含 `Microsoft YaHei UI`**
  （真机装了，但 `.ttc` 未被 offscreen 枚举到）。因此图里中文是 Qt 的替换字体画的，
  字形与真机浮窗**不完全一样**；字号与折行不受影响（都由 `QFontMetrics` 按同一个字号算）。
  「字体字形的真实观感」不能靠这张图判，归 #177 的 ⑤⑥。
- 棋盘格边长、示例画面配色只是观感示意，不是规格。
- 预览画布在真实现里会随调参页宽度自适应（#176 决策 1：1:1 优先、超宽才降级）；
  本图固定在 1:1。
