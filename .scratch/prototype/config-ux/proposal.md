## 四个待定问题（first-principles：现状 → 提议 → 备选）

### Q1 保存后给什么反馈？路径显示在哪？「打开配置目录」放哪？

- 现状：点 OK 写盘并**关窗**，零反馈；拖窗口也会静默写盘。
- **提议（件里画的）**：`保存` 后**不关窗**，页脚左侧变绿色 `✔ 已保存 12:03:45`，直到下次改动变黄色 `● 有未保存的改动`；路径常驻在页脚、可选中复制；`打开配置目录` 紧跟路径右侧（`QDesktopServices.openUrl`）。
- 备选 B：保留 OK/Cancel，OK 关窗，改由**重开面板时的 banner 副行**显示"上次保存 12:03 · 路径"。
- 备选 C：3 秒 toast —— 不推荐：一次性信息，"存没存"没有持久证据可回看。

### Q2 重开/重启后怎么回显？Key 怎么显示？

- 现状：base_url/Model 明文回显（有值就是有值），API Key 用 `Password` 掩码但**读到什么填什么**，看起来像一个已填的空框 —— 无法区分"没配"和"配了"。
- **提议**：base_url / model 明文；API Key **永不回显明文**，输入框恒为空，placeholder 写 `••••••••••••  已保存 51 字符 · 留空 = 不改动 · 输入 = 覆盖`；未设置时 placeholder 写 `尚未设置（明文不会回显）`；旁边 `清除`（二次确认）。保存语义随之改为"留空 = 不改动，输入 = 覆盖"。
- 备选：加"眼睛"按钮临时显示明文 —— 反对：肩窥面 + 对"确认存没存"没有增量（长度 + 字符数已经证明存了）。
- 待你定的细节：banner 只显示 host（件里如此）而面板显示完整 URL，要不要反过来？

### Q3 未配置 / Mock / 已配置三态在面板与浮窗上怎么呈现？

- **提议**：见上表；浮窗状态行复用现有 `status_text` 位置（左下、灰色 Consolas 9，已有）。
- 关键取舍：未配置时的状态行是**常驻**还是**几秒后消失**？（件里是常驻 —— 因为"为什么没有译文"应该随时可查。）
- Mock 时那句"不代表真实翻译质量"要不要常驻？（件里常驻，与静音/暂停的 `[Paused]` 共用同一行，可能挤。）

### Q4 保存语义：输入即存 / 点保存才存 / 取消是否丢弃 / 拖动窗口的隐式保存留不留？

- 现状：**没有显式保存按钮**（只有 OK/Cancel），且 `_persist_geometry()` 在每次鼠标释放后整份 `S.save()` —— 所以**只是拖一下窗口，磁盘上就出现了 setting.json**。这正是你文件里 base_url/api_key/model 为空的来源：文件存在 ≠ 你配置过。
- **提议**：`保存` = 唯一写 `provider / prompt / display` 的动作；`关闭` 无改动直接关、有 dirty 弹三选（保存 / 丢弃 / 取消），不再有 OK/Cancel；窗口几何**仍然自动记录**（否则重启丢位置），但在面板里明写"窗口位置与大小会自动记录"，且**不触发** `✔ 已保存` 反馈。
- 备选 D：输入即存（去掉保存按钮）—— 反对：没有"存没存"的证据，且 provider 半填状态下就已被引擎读走。
- 备选 E：几何拆到独立 `window.json`，让 `setting.json` 只在真正配置后出现 —— 收益是"文件存在 = 配置过"这条叙事成立，代价是多一个文件 + 迁移。
