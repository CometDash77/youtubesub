## 2. 两条必须带走的结论

### 2.1 O3 = headless 指纹，不是产品缺陷

- 真实字幕请求走的是 **XHR**（不是 fetch），请求 URL 里明写 `cbr=HeadlessChrome`。
- headless：`200` + `text/html` + **0 字节**；手动重取同一 URL 也是 0 字节；站点自己的字幕 DOM 也是 `null`（即站点自己也没拿到字幕）。
- headed（去掉 `--headless`）：同一 URL → `200` + `application/json` + **8079 字节** json3 → userscript 解析出 **61 条 cue** → `/status` 变 `state=ok`，浮窗显示真实歌词 + `【译】` 译文。
- 上一份交接猜的"YouTube 把 `window.fetch` 包装器换掉了"**已被证伪**：tracer 取到的内层函数源码与 hook 包装器逐字一致；XHR 钩子也在；人工派发合成事件能让 `cueCount` 从 -1 变 2。
- 推论：`--live` **不要加 `--headless`**（那条诊断在 headless 下必然 `no_cues`，是环境结论）。MANUAL-ACCEPTANCE 的 L2 已按此改写。

## 6. 坑（能省你几小时，含本会话新踩的）

- **不是 git 仓库**：没有回滚。改动前先跑基线（`node --test` + 非浏览器 pytest 子集），或手工备份。
- **`--live` 不要加 `--headless`**（§2.1）。
- **不要 kill 用户自己的 chrome.exe**；E2E 一律独立 profile + 空闲端口，只杀自己启动的进程。
- **不要碰 `%APPDATA%/SubOverlay/setting.json`**（存真实 API Key）。demo/live 用临时 APPDATA + mock；测试同理（本会话已修一处违反）。
- **PowerShell 控制台是 cp936**：打印含 `♪` 等字符的 JSON 会 `UnicodeEncodeError` 并让脚本崩在中途（本会话为此白跑两次）。用 `$env:PYTHONIOENCODING="utf-8"` 或 `json.dumps(..., ensure_ascii=True)`。
- **诊断脚本要自己落盘**：harness 会删临时目录；探针统一用 `.scratch/probe/_tee.py` 把输出 tee 进 `.scratch/probe/logs/`。
- node 测试必须用 glob：`node --test "tests/*.test.mjs"`（传目录会 MODULE_NOT_FOUND）；仓库没有 `package.json`。
- 本机 DNS 污染：访问公网必须走代理 `127.0.0.1:10809`；loopback 请求要绕开代理（测试用 `http.client` 最稳）。
- 夹具页 origin 必须是真的 `http://127.0.0.1:<port>`；timedtext 路径必须含字面量 `youtube`；`/media.wav` 必须支持 Range，否则 seek 断言假红。
