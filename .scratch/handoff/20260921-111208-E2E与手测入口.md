## 2. 本会话抓出并修掉的 4 个真 bug（都是先红后绿）

1. **cues 到达会清零播放时钟**（[engine.py](desktop/suboverlay/engine.py)）。
   现象：暂停中切字幕轨 / SPA 重载轨道后，浮窗空白直到下一次播放器事件（暂停时永远不来）。
   根因：`handle_event` 的 cues 分支无条件 `src.sync = SyncState()`。
   修法：同 source 保留活时钟（同 source = 同一视频），新 source 仍从零开始。
   证据：`test_cues_refresh_keeps_a_live_clock` + E2E 的 SPA 用例。这个 bug 就是 E2E 第一次跑红的产物。

2. **click-through 没有可达的解锁路径**（[overlay.py](desktop/suboverlay/overlay.py) + [app.py](desktop/app.py)）。
   现象：开启 click-through（WS_EX_TRANSPARENT）后窗口忽略鼠标，右键菜单本身也点不到，只能杀进程；而菜单文案写着"Ctrl+Alt+U to unlock"，那个热键当时并不存在。PROGRESS 曾声称"click-through+解锁"已做，属**文档与实现不符**。
   修法：实现 Ctrl+Alt+U 全局热键 + `hotkey.py`；文案与新行为对齐。

3. **菜单构造时序**（[app.py](desktop/app.py)）。
   `_ct_action` 只在 `run()` 里由 `_menu()` 创建，而热键定时器先启动 → 极小窗口期按热键会 AttributeError。
   修法：`self.overlay._ctx_menu = self._menu()` 移进 `__init__`。由 App 级测试红暴露。

4. **YouTube 的 Trusted Types 让页面钩子静默失败**（本会话最重要）。
   现象：真实 youtube.com 上 userscript 成功连上 WS、面板显示 `connected`，但永远抓不到一条字幕；只有一条 `console.warn`。浏览器 Log 的原话：
   `This document requires 'TrustedScript' assignment. The action has been blocked.`
   `[youtubesub] page hook injection failed TypeError: Failed to set the 'textContent' property on 'HTMLScriptElement'…`
   根因：`el.textContent = code` 在 `require-trusted-types-for 'script'` 的页面上被拒。
   修法两条腿：
   - 注入三级回退：`GM_addElement`（Tampermonkey 生产路径，带扩展特权）→ `trustedTypes.createPolicy(...)` 的 TrustedScript → **主世界** `new Function(code)()`。第三级在不满足条件时**主动跳过**（若 `unsafeWindow !== window` 说明身处 userscript 沙箱，装上去只会装进错的 realm，比失败更糟）。
   - 失败必须可见：`register` 帧携带 `hook_error` → engine meta → `/status` → 浮窗状态行 + 页面面板 `[NO PAGE HOOK]`。

## 6. 坑（能省你几小时）

- **不是 git 仓库**：没有 diff、没有回滚。改任何文件前先想清楚；建议改动前手工备份或先跑一次全量测试留基线。
- **不要 kill 用户自己的 chrome.exe**（他机器上有常驻 Chrome 在用）。E2E 一律用独立 `--user-data-dir` + 空闲调试端口；harness 只 kill 自己启动的进程。同理**不要碰用户真实设置** `%APPDATA%/SubOverlay/setting.json`（里面存 API Key）：demo/live 都用临时 APPDATA + mock provider。
- **两处"测试特权"绝不可进生产路径**：Chrome `--disable-web-security`（顶替 GM_xmlhttpRequest 的 CORS 旁路）与 CDP `Page.setBypassCSP`（顶替 GM_addElement 的 CSP/TT 特权，仅 `--live` 用）。真实 Tampermonkey 不需要它们。
- **夹具页 origin 必须是真的 `http://127.0.0.1:<port>`**，不能用 `*.localhost`：WS 的 `origin_allowed` 认字面量 `127.0.0.1`，否则 403。timedtext URL 路径必须含字面量 `youtube` 才过 `isTimedtextUrl`。
- **夹具的 `tOffsetMs` 必须是"段内小偏移"**（真实 json3 语义），不是绝对时间戳：我第一版写成 `s+100` 导致 last_off 越界、分句被合并、演示显示拼接串。
- **`/media.wav` 必须支持 HTTP Range**（206）：不支持时 Chrome 把 seek 钳到已缓冲处（实测只有 ~0.5s），E2E 的 seek 断言会**假红**。
- **node 测试必须用 glob**：`node --test "tests/*.test.mjs"`；传目录会 MODULE_NOT_FOUND（Node 22.23.1）。仓库**没有 package.json**。
- **本机 DNS 污染**：访问公网必须走代理 `127.0.0.1:10809`；loopback 请求要绕开代理（测试里用 `http.client` 最稳，`urllib` 会读代理环境变量）。
- **PowerShell 执行策略拦 .ps1**（截图脚本等需 `-ExecutionPolicy Bypass`），`npm.ps1` 同样受限。
- **CDP `/json/list` 里会混入扩展的 `background_page` target**，要挑 `type == "page"`。
- 演示时控制台可能把 `【译】` 显示成乱码（cp936）——纯显示层，浮窗才是真证据。
- 本 harness 的文件编辑策略：**要在同一个程序里先 read 再 edit**，否则报 "file has not been read"。

## 9. 安全与隐私

- 本文档**不含任何密钥**。用户的真实 API Key 在 `%APPDATA%/SubOverlay/setting.json`，上一会话从未读取、复制或记录。
- `GET /status` 会回显字幕文本，且**只允许 loopback**；无 provider 时不回显 UI 内容。不要把服务绑到非 loopback。
- `GET /health` 与 `/status` 均未加 `Access-Control-Allow-Origin`：**/status 尤其不能加**，否则任意网页可跨源读取用户字幕文本。E2E 里靠 `--disable-web-security` 旁路，属测试专用。
