## 3. 环境陷阱备忘（增量；旧坑见 134318 handoff §3/§4 仍然全部有效）

- **DSH 宿主给工具会话注入 ELECTRON_RUN_AS_NODE=1**：electron.exe 被降级成纯 Node 跑，import { BrowserWindow } from "electron" 直接 SyntaxError（no named exports）——**GUI 冒烟前必须清空该变量**（cmd: set ELECTRON_RUN_AS_NODE=）。另：Electron 44 的 electron.exe 拒绝 --enable-logging（bad option，别加）。
- **GUI 冒烟可行且验证有效的模式**（本会话跑通）：pwsh 工具会话与 explorer 同 session（=2，有交互桌面）；用 Start-Job + cmd 重定向全套 stdout/stderr 到文件，Start-Sleep 12~14s 后 taskkill /IM electron.exe /T /F 杀整树，再读 app/skeleton.log（SKELETON_LOG 指定）。健康链 = scene=base boot → 热键注册 true → WS 127.0.0.1:9877 → did-finish-load + 桥探针 → renderer painted。
- **run_code 工具的 120s 默认 deadline 会截断 job_output(wait:true) 的长等待**——要等 CI/长任务时把 run_code 本身的 timeoutMs 提到 600000。
- **run_code 模板字符串里出现反引号会截断整个字面量**（本次在 main.ts 注释里写了带反引号的词直接炸「Unterminated template」）——往 write/edit 的 content 里塞内容时，注释里不要用反引号修饰。
- **gh 轮询 CI 用 --commit <短sha> 有延迟**（push 后 1~2 分钟才查得到 run）；后台轮询 job 收敛后直接 gh run view <id> --json conclusion 最稳。
- 旧坑仍有效：Node 22 strip-only 禁 TS 参数属性（tsc 不报、运行时才炸）；npm 一律 npm.cmd + cmd /c 验真；pwsh 单命令 120s 上限 → 长命令 run_in_background；**data/translations.db 有未提交改动——维护者领地：不回退、不提交**，git add 显式点名文件；.scratch/ 在 .gitignore 但历史 handoff 是 add -f 入库的，本次交接沿用。
